| 2026-09-21 | [[../slices/S-02-programs-from-the-treasury\|S-02]] | The treasury creates and changes programs over Kafka (`treasury.capacity`, capacity updates keyed by `programId`), and an authenticated client reads a program's availability: `GET /programs/:programId/availability` answers limit, reserved, available, currency, `overcommitted` and `asOf` in integer minor units. Every business route needs a bearer JWT (HS256, `JWT_SECRET`); health and the documentation do not. A repeated message is counted as a duplicate, an older `eventTime` is recorded stale, a malformed or refused message is dead-lettered to `treasury.capacity.dlq` with the reason in its headers while consumption continues. `npm run dev:token` mints a token, `npm run dev:treasury` publishes an update, and `docker compose up --wait` ends with the sample program `PRG-1` at 10 000 000.00 USD. Every log line is JSON with a correlation id per request and per message. | AC-20, AC-23, AC-24, AC-25, AC-32, AC-33, AC-35, AC-36, AC-37, AC-40, INV-10 | ADR-0005, ADR-0006, ADR-0007 (all accepted before the slice); A-06 and A-13 amended, glossary extended | No reservations yet (S-03), so `reserved` is always 0 and a program is never overcommitted in practice. The snapshot message type is rejected as unknown until S-06. Only HS256 with one shared secret (ADR-0005); the development secret is the compose default and is refused in production. Four minors from the fourth review, deliberately carried into the next slice: the dead-letter publish runs inside the message store transaction (a slow broker can time it out after the publish and produce a second dead letter on redelivery, never a lost one); the AC-40 test's "two ids differ" line compares two constants; an oversized amount in the availability mapper is labelled by currency rather than field; and a stale update with another currency is recorded `stale`, now written down in A-13 (5) but not pinned by a test. |
| 2026-09-22 | [[../slices/S-03-reservations-and-capacity-invariant\|S-03]] | An authenticated client reserves capacity for an invoice: `POST /programs/:programId/reservations` with `invoiceId`, `invoiceAmount` in minor units and `invoiceCurrency` answers `201` with the reservation (`reservedAmount`, `held`, `status` `active`, `source` `client`) and availability drops by the same amount. Refusals carry stable codes: `400 VALIDATION_FAILED` naming the field, `404 PROGRAM_NOT_FOUND`, `409 RESERVATION_ALREADY_EXISTS` with the original reservation in the body, `422 CAPACITY_EXCEEDED` with `available`. Capacity is never overcommitted, proven with 25 parallel requests across two service instances on one database (a row lock per program, ADR-0008). When the treasury raises or lowers a limit, availability follows and a program below its usage reads `overcommitted` with every `held` kept. Every capacity movement is in an append-only ledger whose balances chain and are checked after every e2e test. A currency code is uppercased on both the HTTP and the Kafka edge, so `usd` means `USD` (A-10 amended). | AC-01, AC-02, AC-03, AC-04, AC-05, AC-08, AC-09, AC-21, AC-22, INV-01, INV-03, INV-04, INV-09, INV-11 | ADR-0008 (accepted before the slice); A-10 amended, glossary gains `source`, `Reservation identity`, `Currency code` | Same-currency reservations only: an invoice in another currency answers `422 CURRENCY_MISMATCH` until S-04 brings the client-supplied rate (then AC-07's `400` naming `rate`). No release and no read of one reservation yet (S-05); `held` equals `reservedAmount` for every reservation. `source` `reconciliation` is a legal state of the table but nothing produces it until S-06. The ledger check is a test helper, not a runtime guard. |
| 2026-09-23 | [[../slices/S-04-cross-currency-reservations\|S-04]] | A client reserves an invoice denominated in another currency than the program by sending `rate`, a decimal string of at most eight places: `POST /programs/:programId/reservations` converts once, rounds half up to the program's minor unit, stores the rate on the reservation and answers `201` with `reservedAmount`, `held` and the rate in canonical form (`"1.10"` reads back `"1.1"`). Each currency keeps the minor unit ISO 4217 gives it, so 1 000 JPY at `0.0067` reserves 6.70 USD and 1.00 USD at `0.30712` reserves 0.307 KWD, rather than both being treated as two decimals. A rate is required across two currencies and must be one within a currency; either mistake, and a rate that is not a positive decimal of at most eight places, answers `400 VALIDATION_FAILED` with `details` naming `rate`. The interim `422 CURRENCY_MISMATCH` on a reservation is gone: a reservation can no longer produce it. | AC-06, AC-07, INV-08 | ADR-0006 (accepted before the slice; its rate half applies here unchanged); A-10 amended twice, for the minor unit exponent and the canonical rate, glossary gains `Minor unit, minor unit exponent` | No release yet (S-05), so `held` still equals `reservedAmount` on every reservation and the stored rate is not converted back yet. The `reservations.rate` column has no `CHECK (rate > 0)`; nothing in the service can write such a row, since the mapper is the only writer, but the table's other constraint sets the pattern and this one is missing. The glossary still illustrates `Adapter`, `Seam` and `Fake` with a `RateProvider` and a config rate table that A-02 decided against, so the ubiquitous language teaches a seam the service does not contain. Run on Opus although the slice is `risk: high`, and both review rounds ran on Opus too because the Fable credits were exhausted, so the model independence `CLAUDE.md §8` buys was absent for this slice. |
